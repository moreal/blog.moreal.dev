# 리팩터링 루프

한 번 실행에 장부 항목 하나를 처리한다. 동작은 그대로 두고 읽기 쉽게 바꾼 뒤 main에 커밋 하나를 남긴다. 이전 실행의 기억은 없다. 장부와 git이 상태의 전부다.

## 원칙

- **동작을 바꾸지 않는다.** 라우트 응답의 형태, URL, 빌드된 HTML은 그대로여야 한다. 버그를 발견하면 고치지 말고 보고에 적는다.
- **주석 대신 코드로 말한다.** 주석이 설명하던 내용은 이름, 타입, 함수 분리, 테스트 이름으로 옮기고 주석을 지운다. 어디로도 옮길 수 없는 제약만 주석으로 남긴다.
- **사용자의 작업을 건드리지 않는다.** 이 작업 트리에서는 사용자가 원고를 쓰고 있다. `git status --porcelain -- <파일>`의 출력이 비어 있지 않은 파일은 수정 중이므로 읽기만 한다. `git stash`, `git reset`, `git checkout .`, `git add -A`, `git add .`은 쓰지 않는다.

## 무엇을 고치나

| 보이는 것 | 고치는 방법 |
|---|---|
| 라우트·컴포넌트 안에 판단 로직이 섞여 있음 | 순수 함수로 떼어 모듈로 옮기고 테스트를 붙인다 |
| 같은 코드가 두 곳 이상에 있음 | 한 곳으로 모은다 |
| 한 글자·축약 이름, 하는 일을 말하지 않는 이름 | 뜻이 드러나는 이름으로 바꾼다 |
| 한 함수가 여러 일을 함 | 이름 붙은 작은 함수로 나눈다 |
| 설명 주석이 있어야 읽히는 코드 | 이름과 구조로 옮기고 주석을 지운다 |
| 참조가 없는 export·함수·CSS 규칙 | grep으로 참조가 없음을 확인하고 지운다 |

모듈 경계:

- `src/admin/lib/`는 `node:fs`에 닿는 서버 전용 코드다. `src/admin/ui/`에서 import하지 않는다.
- 서버와 브라우저가 함께 쓰는 코드는 `src/admin/shared/`에 둔다.
- `src/admin/lib/types.ts`에는 타입만 둔다. ui가 import하므로 런타임 값이 들어가면 node 코드가 브라우저 번들에 끌려간다.
- 사이트 쪽 로직은 `src/lib/`에 두고 `src/pages/`와 `src/components/`는 얇게 유지한다.
- 테스트는 대상 옆의 `*.test.ts`에 `node:test`와 `node:assert/strict`로 쓴다.

하지 않는 것: 의존성 추가, 포매팅만 바꾸기, 같은 수준의 스타일끼리 바꾸기, 기능 추가, 문자열째 HTML에 들어가는 코드(인라인 스크립트 등)의 내용 바꾸기.

## 절차

스크립트 경로는 `S=.claude/skills/refactor`로 줄여 쓴다.

1. **대상 고르기.** `$S/init-ledger.sh`를 실행한다(장부가 있으면 그대로 둔다). `.claude/refactor-ledger.md`에서 위에서부터 `- [ ]` 항목을 고르되, 수정 중인 파일은 건너뛴다. 남은 `[ ]`이 모두 수정 중인 파일이면 9단계로 간다.
2. **판단.** 대상과, 그것이 import하는 파일과 그것을 import하는 파일을 읽는다. 위 표에 해당하는 것이 없거나, 있어도 이름 한두 개를 바꾸는 정도라면 장부의 그 줄을 `- [-] <경로> — <이유>`로 바꾸고 9단계로 간다.
3. **기준선.** `$S/build-diff.sh snapshot`, `yarn test`, `yarn run check`를 실행해 통과를 확인하고, check 요약 줄의 경고·힌트 수를 기억한다.
4. **동작 고정.** 옮기거나 바꿀 로직에 테스트가 없으면 지금 코드에 대한 테스트를 먼저 쓰고 통과시킨다. 테스트할 수 없게 묶여 있는 로직은 export하거나 경로 같은 고정값을 인자로 받게 하는 정도까지만 먼저 바꾸고 테스트를 쓴다.
5. **리팩터링.** 대상 파일이 다른 파일과 겹치는 코드를 들고 있으면 지금 한 곳으로 모은다. 대상과 무관한 두 파일 사이의 중복은 그 파일의 차례에 한다. 함께 고쳐야 하는 파일도 수정 중이 아니어야 하며, 수정 중인 파일에 닿는 변경은 하지 않는다.
6. **검증.** 셋 다 통과해야 한다.
   - `yarn test`
   - `yarn run check`: 오류 0개, 경고·힌트가 기준선보다 늘지 않음
   - `$S/build-diff.sh compare`: `IDENTICAL` 또는 `BUNDLE-ONLY`. `DIFFERS`일 때 달라진 페이지가 모두 그 사이 수정된 원고(`git status`의 `20xx/` 파일)에서 나온 것이면 통과로 본다.
7. **실패.** 원인을 고쳐 두 번까지 다시 검증한다. 그래도 실패하면 자기가 바꾼 파일만 `git checkout -- <파일>`로 되돌리고 새로 만든 파일은 지운 뒤, 장부의 줄을 `- [!] <경로> — <이유>`로 바꾼다.
8. **커밋.** 바꾼 파일을 경로로 하나씩 `git add`하고 커밋한다. 메시지는 한국어로 쓴다. 첫 줄은 무엇을 했는지 짧게, 본문은 무엇을 어떻게 왜 바꿨는지 쓴다. `BUNDLE-ONLY`였으면 본문에 "클라이언트 번들 변경"을 적는다. 메시지 끝에는 `Co-Authored-By: <자신의 모델 이름, 예: Claude Opus 5> <noreply@anthropic.com>`을 붙인다. 커밋한 뒤 장부의 줄을 `- [x] <경로> — <짧은 해시>`로 바꾼다. 장부는 gitignore되어 있으므로 커밋하지 않는다.
9. **보고.** 이 보고는 루프를 돌리는 메인 에이전트가 읽고 다음 반복을 예약하거나 루프를 끝낸다. 마지막 줄은 그 에이전트에게 주는 지시다. `남은 대기`는 장부의 모든 `[ ]` 줄 수다. 아래 형식으로 끝낸다.

```
결과: 완료 | 손댈 것 없음 | 보류 | 없음 — <경로> (<해시 또는 이유>)
남은 대기: <n>개
루프: 계속 — 기다릴 것이 없으니 다음 반복은 60초 뒤
```

남은 `[ ]` 중 수정 중이 아닌 것이 없으면 마지막 줄을 `루프: 종료 — ScheduleWakeup을 stop: true로 호출`로 쓰고, 장부의 `[!]` 항목과 수정 중이라 건너뛴 파일을 모두 나열한다.
